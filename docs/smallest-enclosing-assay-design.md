# Design spike: smallest-enclosing-assay leverage operator and proxy-debt ledger

Status: **design spike** (no implementation). Tracks GitHub issue #8.

This document is the deliverable for the #8 design spike. It formalizes the
model, the human-in-the-loop workflow, the data contracts, and the Lab Tracker
integration seam, and closes with the issue's acceptance-criteria checklist. It
deliberately introduces **no new retained-v1 entity** and **no autonomous graph
writes**: the first implementation emits a versioned external artifact (the
*Dataset Design Contract*) plus a graph-linked note/goal, all human-gated.

## 1. Problem and intent

A proposed measurement is rarely atomic. "Measure CNMa secretion by the fat
body" names a target, a modality, and a compartment, but leaves the motivating
contrast partly implicit and ignores that a broader assay could answer the same
question *and* several sibling questions at little extra acquisition cost.

The product opportunity is a **human-gated compiler** from a point-query
measurement to the **smallest enclosing high-leverage assay** that provably
preserves the original scientific intent. Lab Tracker owns the *semantic record*
of that reasoning — not assay booking, instrument control, LIMS, ELN, or OED
execution.

## 2. Measurement factorization (the type system)

Every measurement is factored into a fixed set of **factors**, each drawn from a
typed vocabulary. This factorization is the backbone of both the transformation
model (§3) and the proxy-debt ledger (§5).

| Factor | Meaning | Example (CNMa) |
| --- | --- | --- |
| `construct` | the intended, motivating claim referent | CNMa secretion by the fat body |
| `target` | the measured entity | CNMa (gene/peptide) |
| `modality` | what physical quantity is read out | secretion (regulated release) |
| `specimen_or_compartment` | tissue / cellular compartment | fat body |
| `contrast` | the comparison that gives the readout meaning | fed vs. starved |
| `biological_resolution` | grain of the biological answer | tissue / cell-type / single-cell |
| `temporal_resolution` | grain over time | none / timecourse |

The `construct` is privileged: it is the *birth* referent and is never
rewritten by the operator (see the Birth Requirement, §4). The other six factors
are the axes the operator is allowed to move along.

## 3. Typed candidate-transformation model

Candidate assays are generated by applying **typed transitions** to one or more
factors. Each factor has its own **partial order** (a directed acyclic "climbs
to" relation), and candidates live in the product of these orders. We
deliberately model this as a **typed factor graph / partial order, not a strict
mathematical lattice**: joins and meets need not exist, and some factors (e.g.
`modality`) are not ordered at all — they are substitution sets.

Transition kinds:

- **`scope_climb`** — move up a target partial order.
  `CNMa ⊂ neuropeptide transcripts ⊂ secreted-protein transcripts ⊂ transcriptome`.
- **`modality_substitute`** — swap the read-out physical quantity.
  `secretion → transcription` (a *proxy*; see §5).
- **`contrast_reveal`** — make a latent contrast explicit. `∅ → {fed, starved}`.
- **`resolution_refine`** — increase biological or temporal resolution.
  `tissue → cell-type`; `single point → timecourse`.
- **`factorial_expand`** — add an orthogonal factor level (a new arm).

**Evidence for every transition is mandatory.** A transition is a typed edge
carrying:

```yaml
transition:
  kind: modality_substitute          # one of the kinds above
  from: {modality: secretion}
  to:   {modality: transcription}
  relation: proxy                     # direct | proxy | surrogate | derived | unknown
  evidence_refs:                      # canonical URI + content hash, never inlined
    - uri: "doi:10.xxxx/..."
      sha256: "..."
  assumptions:
    - "transcript abundance predicts peptide production"
  failure_modes:
    - "post-transcriptional regulation decouples mRNA from secreted peptide"
```

A `scope_climb` or `resolution_refine` typically carries `relation: direct`
(the broader measurement still contains the original as a marginal). A
`modality_substitute` typically carries `relation: proxy` and therefore incurs
**proxy debt** (§5). No transition may assert `relation: direct` for a modality
substitution.

## 4. The Birth Requirement (irreversibility regularizer)

Every recommendation must, by construction:

1. keep the motivating `construct`/question **explicit and unchanged**;
2. state whether the birth construct is **measured directly or only proxied**;
3. preserve a design that can still answer the original question under listed
   assumptions (the *minimum-sufficient* member of the Pareto set, §6, is the
   witness);
4. **justify each breadth increase with one or more enumerated, accepted
   Questions** (no expansion without a sibling question to pay for it);
5. stop climbing when marginal cost or burden rises materially (§7).

Mechanically, the birth question id is carried verbatim through every candidate
and contract; the operator has no code path that mutates it. The UI renders the
birth construct and its direct/proxy status **prominently** on every candidate.

## 5. Proxy-debt ledger

A modality substitution is lossy until validated; the graph must **never
silently equate a convenient proxy with the motivating construct**. For each
proxy relation the ledger retains:

- birth construct;
- operationalized measurement;
- relation type (`direct | proxy | surrogate | derived | unknown`);
- assumptions required for interpretation;
- supporting evidence and source references (URI + content hash);
- known failure modes;
- validation status and confidence;
- the unresolved direct measurement (the residual claim);
- a proposed calibration or orthogonal-validation assay.

### Reuse of published vocabularies (minimal novelty)

Per the project's ontology guidance, prefer existing published terms and add
Lab-Tracker-specific vocabulary only for semantics the standards do not cover:

- **PROV-O / PAV** for provenance, revision, and derivation of the contract and
  of each candidate from the birth intent (`prov:wasDerivedFrom`,
  `prov:wasGeneratedBy`, `pav:createdBy`, `pav:previousVersion`).
- **ECO** (Evidence & Conclusion Ontology) for the *kind* of evidence backing a
  transition or a proxy assumption.
- **OBI / OBO** for assay, investigation, and specimen terms where they fit; use
  OBO-style `deprecated` / `replaced_by` patterns for retired candidates.
- **CiTO** for scholarly relations to supporting/refuting references.

Lab-Tracker-specific novelty is limited to the *application-level* notion of a
proxy-debt currency (`residual_claim`, `proxy_debt` weighting) that these
standards do not express.

## 6. Output: a three-design Pareto set (not one opaque optimum)

The operator recommends a **Pareto set**, always including a negative option:

1. **Minimum-sufficient assay** — smallest feasible design that answers `q0`.
   This is the Birth Requirement witness.
2. **Recommended high-leverage assay** — best trade-off across original-question
   information, portfolio information, reuse, cost, and proxy risk.
3. **Reuse-maximized assay** — broader design, with each incremental measurement
   explicitly linked to the sibling question(s) that justify it.

The summary renders the **delta from the original proposal** for each option and
must be able to return **"do not broaden"** — i.e. recommend the
minimum-sufficient design when regularizers (marginal cost, proxy debt, burden)
outweigh reuse benefit.

### Utility model

A research-facing scoring function (used to *rank and explain*, not to
autonomously decide):

```text
U(a) = Σ_q w_q · EIG(q; a)            # original + portfolio information
     + λ_reuse · R(a, Q)              # bounded reuse / atlas-tile composability
     - λ_cost  · C(a)                 # acquisition + downstream cost
     - λ_proxy · D_proxy(a, q0)       # construct→readout substitution debt
     - λ_burden · B(a)                # sample, labor, storage, analysis, governance
```

The **MVP does not attempt full Bayesian OED.** It begins with deterministic
coverage, feasibility, marginal-cost, and validity **rules**; `EIG` is supplied
later by domain-specific adapters. `D_proxy` is a monotone function of
unvalidated proxy debt from §5, so an unvalidated modality substitution is
always penalized.

### Marginal-cost stopping rule (explicit and inspectable)

Breadth climbing halts when the **marginal utility per marginal cost** of the
next transition drops below an inspectable threshold τ:

```text
stop when  [U(a ∪ t) − U(a)] / [C(a ∪ t) − C(a)]  <  τ
```

Every candidate records which transition was the last accepted one and which was
the first rejected one *and why* (`τ` breach, feasibility, or proxy-debt cap), so
the stopping decision is auditable rather than a hidden optimum.

## 7. Worked example (static, CNMa)

Birth: *"starvation increases fat-body CNMa secretion"* — `target: CNMa`,
`modality: secretion`, `compartment: fat body`, `contrast: {fed, starved}`.

| Option | Factorization | Birth relation | Sibling questions paid for | Note |
| --- | --- | --- | --- | --- |
| **Minimum-sufficient** | CNMa peptide secretion assay, fed/starved, fat body, tissue | **direct** | — | Answers `q0` directly; no proxy debt. |
| **High-leverage** | fed/starved fat-body **bulk RNA-seq** | **proxy** (secretion→transcription) | "which neuropeptides are nutrient-responsive?", "fat-body secretory program under starvation?" | Lower marginal cost per question; incurs proxy debt (residual: secretion unmeasured). Recommends pairing with an orthogonal secretion readout. |
| **Reuse-maximized** | fed/starved fat-body **single-cell** multi-tissue atlas tile | **proxy** | the above + cell-type heterogeneity, atlas composability | Highest reuse `R`; highest cost/burden. Flagged if τ or burden cap is breached. |

The operator emits all three, marks direct-vs-proxy prominently, and — if the
proxy debt of options 2–3 exceeds their reuse benefit for the current portfolio
— returns **"do not broaden: minimum-sufficient"** as the recommendation.

## 8. Data contracts

Exported as JSON/YAML with PROV-compatible external-artifact references.

### `MeasurementIntent`

```yaml
construct: CNMa secretion by the fat body
claim_or_estimand: starvation increases fat-body CNMa secretion
birth_question_id: <lab-tracker question uuid>     # never mutated
target: CNMa
modality: secretion
specimen_or_compartment: fat body
contrast: {factor: nutrient_state, levels: [fed, starved]}
biological_resolution: tissue
temporal_resolution: null
required_controls: []
constraints: []
```

### `AssayCandidate`

```yaml
name: fed/starved fat-body bulk RNA-seq
factorization:
  target_scope: transcriptome
  modality: transcription
  specimen_or_compartment: fat body
  contrast: {factor: nutrient_state, levels: [fed, starved]}
  biological_resolution: tissue
transitions: [<typed transition records, §3>]
contains_birth_readout: false
birth_construct_relation: proxy
justifying_question_ids: [<accepted question uuids>]   # Birth Requirement #4
capability_ref: yale-core://example/rna-seq
cost_model_ref: sha256:...
output_schema_ref: uri:...
score: {U: ..., EIG: ..., reuse: ..., cost: ..., proxy_debt: ..., burden: ...}
```

### `ProxyDebtRecord`

```yaml
construct: fat-body CNMa secretion
measurement: fat-body CNMa transcript abundance
relation: proxy
assumptions:
  - transcript abundance predicts peptide production
  - peptide production predicts regulated release
supporting_evidence: [{uri: "doi:...", sha256: "..."}]
failure_modes: [post-transcriptional decoupling]
validation_status: unvalidated
confidence: low
residual_claim: secretion remains unmeasured
proposed_validation: orthogonal peptide secretion assay
```

### `DatasetDesignContract` (the exported artifact)

A versioned bundle of the `MeasurementIntent`, the Pareto `AssayCandidate` set,
and the `ProxyDebtRecord`s, plus PROV-O/JSON-LD provenance
(`prov:wasDerivedFrom` the birth question). Stored as an **external artifact**
referenced by canonical URI + `sha256` content hash — the same seam Lab Tracker
already uses for external artifacts — and linked to a graph note/goal. **No new
retained-v1 entity is introduced.**

## 9. Human-in-the-loop workflow (MVP)

1. Select an existing hypothesis-driven Question.
2. Draft a factored `MeasurementIntent` from the question and project context.
3. **Scientist edits and accepts** the factorization.
4. Read a small curated YAML capability catalog and target/modality partial
   orders.
5. Enumerate a bounded set of candidate expansions.
6. Score with deterministic rules: birth-question coverage, enumerated
   sibling-question coverage, marginal cost, feasibility, proxy debt.
7. Display the three-design Pareto summary with explicit deltas.
8. **Scientist / core-expert review.**
9. Export a versioned Dataset Design Contract + proxy-debt ledger + provenance
   references.
10. Link the accepted contract to later sessions, datasets, analyses, claims.

**Human review precedes every graph write** — consistent with Lab Tracker's
"AI can suggest; only a person commits" rule. The operator has no autonomous
commit path.

## 10. Fit with Lab Tracker, and non-goals

Lab Tracker owns the semantic record. It references external capability,
protocol, service-request, simulator, and OED outputs by **canonical URI +
content hash**; PROV-O / JSON-LD is the integration seam; native core-facility
and analysis systems keep their workflows.

**Non-goals (scope fence):**

- Fully automated experimental planning.
- A universal assay ontology in the first release.
- A general-purpose Bayesian OED engine.
- Inferring that a proxy establishes the birth construct.
- Expanding measurements without accepted questions or a bounded workload.
- Reimplementing core-facility operational systems.
- **No LIMS, booking, instrument-control, ELN, or autonomous graph-commit scope.**

## 11. Evaluation questions

- Does the operator surface overlooked contrasts, controls, or metadata *before*
  acquisition?
- Does it improve the birth question's identifiability or precision?
- Do independent scientists find more legitimate reuse questions for the
  resulting dataset?
- How often does the high-leverage recommendation merely say "measure
  everything," and do the regularizers prevent it?
- How often do scientists reject a modality substitution because proxy debt
  exceeds reuse benefit?
- Can core-facility experts audit and correct capability/cost assertions
  efficiently?
