# Workstation HTTPS Serving

Milestone 1 makes the current graph computer a repeatable browser-serving host
for Lab Tracker over HTTPS. The workstation remains the canonical machine, but
external clients reach it through an outbound tunnel instead of a campus-local
IP address or router/firewall port forwarding.

This milestone covers the browser UI and Lab Tracker API. Remote hosted-AI MCP
access is a follow-up milestone because the current MCP server is stdio-only.

## Target Shape

```text
graph workstation
  Lab Tracker API/UI: http://127.0.0.1:8000
  Postgres:           127.0.0.1:5432
  note/file storage:  local workstation disk
      |
      | Tailscale Funnel or another outbound HTTPS tunnel
      v
https://mwcppc01ysbc155.tail79f9d8.ts.net/app
```

Use direct `http://10.x.x.x:8000` only for short Yale-network smoke tests. The
workstation HTTPS shape should bind Lab Tracker to `127.0.0.1` and let the
tunnel publish the HTTPS endpoint.

The current no-custom-domain workstation endpoint is:

```text
https://mwcppc01ysbc155.tail79f9d8.ts.net/app
```

Use this base URL for remote MCP clients:

```text
LAB_TRACKER_MCP_BASE_URL=https://mwcppc01ysbc155.tail79f9d8.ts.net
```

## One-Time Local Setup

Copy the example environment file and fill in real secrets:

```powershell
Copy-Item .env.workstation.example .env.workstation
```

Generate strong values for:

- `LAB_TRACKER_AUTH_SECRET_KEY`
- `LAB_TRACKER_BOOTSTRAP_ADMIN_TOKEN`

Do not commit `.env.workstation`; `.gitignore` excludes it.

For the recommended multi-client runtime, start Postgres:

```powershell
docker compose up -d postgres
```

Then run migrations and serve Lab Tracker on localhost:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\serve-workstation.ps1 -UsePostgres
```

The helper uses `.env.workstation`, requires auth to be enabled, runs Alembic,
and starts:

```powershell
.venv\Scripts\python.exe -m uvicorn lab_tracker.asgi:app --host 127.0.0.1 --port 8000
```

In another shell, verify:

```powershell
.\scripts\check-workstation-serving.ps1
```

Expected:

- `health: ok`
- `readiness: ok`
- `unauthenticated_projects: HTTP 401`

## Create The First Admin

If the database has no users yet, bootstrap one admin from the workstation:

```powershell
$bootstrapToken = "<copy LAB_TRACKER_BOOTSTRAP_ADMIN_TOKEN from .env.workstation>"
$body = @{
    username = "sam"
    password = "<strong-password>"
    role = "admin"
    bootstrap_token = $bootstrapToken
} | ConvertTo-Json

Invoke-RestMethod `
    -Method Post `
    -Uri "http://127.0.0.1:8000/auth/register" `
    -ContentType "application/json" `
    -Body $body
```

After that, admin users can provision editor accounts through the same API.

## Durable Tailscale Funnel

Use Tailscale Funnel when there is no custom domain. This workstation is
configured with:

```text
https://mwcppc01ysbc155.tail79f9d8.ts.net
```

The local Lab Tracker server is kept alive by the Windows scheduled task:

```powershell
Get-ScheduledTask -TaskName "Lab Tracker Workstation Server"
```

Check the public proxy:

```powershell
& "C:\Program Files\Tailscale\tailscale.exe" funnel status
```

Expected:

```text
https://mwcppc01ysbc155.tail79f9d8.ts.net (Funnel on)
|-- / proxy http://127.0.0.1:8000
```

Re-enable Funnel if needed:

```powershell
& "C:\Program Files\Tailscale\tailscale.exe" funnel --bg --yes --https=443 http://127.0.0.1:8000
```

Disable public access:

```powershell
& "C:\Program Files\Tailscale\tailscale.exe" funnel --https=443 off
```

## Durable Cloudflare Tunnel

A durable tunnel needs a Cloudflare account and a domain managed by Cloudflare.
The exact hostname is a human decision, for example:

```text
lab-tracker.example.org
```

Install and authenticate `cloudflared`:

```powershell
winget install --id Cloudflare.cloudflared
cloudflared tunnel login
```

Create and route a named tunnel:

```powershell
cloudflared tunnel create lab-tracker-workstation
cloudflared tunnel route dns lab-tracker-workstation lab-tracker.example.org
```

Create `%USERPROFILE%\.cloudflared\config.yml`:

```yaml
tunnel: lab-tracker-workstation
credentials-file: C:\Users\<you>\.cloudflared\<tunnel-id>.json

ingress:
  - hostname: lab-tracker.example.org
    service: http://127.0.0.1:8000
  - service: http_status:404
```

Run it in the foreground first:

```powershell
cloudflared tunnel run lab-tracker-workstation
```

When it works, install it as a Windows service using the command generated by
Cloudflare Zero Trust or the current `cloudflared service install` flow for the
named tunnel. Keep the service token and tunnel credentials out of Git.

## Security Notes

- Keep Lab Tracker bound to `127.0.0.1` for tunneled serving.
- Do not commit `.env.workstation`, Cloudflare credentials, service tokens, or
  tunnel JSON files.
- Keep `LAB_TRACKER_AUTH_ENABLED=true` for any tunnel.
- Prefer Cloudflare Access in front of Lab Tracker for durable external access.
- For the Tailscale Funnel endpoint, keep Lab Tracker authentication enabled and
  provision specific service accounts for assistant clients.
- Use a real admin/editor account instead of the temporary smoke-test account.
- The MCP server remains stdio-based. Remote agents should run their own MCP
  process with `LAB_TRACKER_MCP_BASE_URL` pointed at the HTTPS endpoint above.

## Rollback

Stop the foreground tunnel with `Ctrl+C`, or stop the Windows service if
installed. Stop Lab Tracker by closing the serving shell. Remove the DNS route
or tunnel in Cloudflare if a public hostname should no longer resolve.
